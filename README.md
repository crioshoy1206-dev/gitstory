# GitStory

세계관(배경·단체·인물)을 구조화해 입력하고, 사건이 생길 때마다 AI가 영향을 반영해 git 커밋처럼 버전으로 쌓는 스토리 창작 보조 앱. 상업 서비스를 목표로 개발 중.

## 지금 상태 (샘플)
- 예시 세계관 3개(아케인, 해리 포터, 짱구는 못말려)로 세계관 편집, 사건 입력, 관계도, 버전 기록(비교, 되돌리기)이 동작한다.
- 변경 내용은 브라우저(localStorage)에 저장된다. "처음 상태로" 버튼으로 예시 초기 상태로 되돌린다.
- 사건 분석은 `/api/analyze`에서 AI가 판단한다(직접 영향·반응도·상황 문장·관계 변화). 숫자 전파는 브라우저가 계산. 요금제별 모델: 무료 = Gemini(`GEMINI_API_KEY`, 기본 gemini-3.8-flash), 유료 = Claude(`ANTHROPIC_API_KEY`, 기본 claude-sonnet-5-5). `AI_MODEL_FREE`/`AI_MODEL_PRO`("제공사:모델")와 `AI_EFFORT`(기본 low)로 조정. 한쪽 키만 있으면 그쪽으로 대신하고, 둘 다 없거나 실패하면 키워드 추정. 요금제는 Firestore `users/{uid}.plan`("pro"면 유료, 결제 연결 전까지 콘솔에서 지정).
- 버전 기록은 커밋 트리로 보이고, 과거 커밋에서 '만약에' 갈래(branch)를 만들 수 있다. 저장 형식은 `{state, commits(모든 갈래), branches, branch, pending, layout}`이고, 갈래 정보가 없는 예전 저장본은 main(화면 이름 '본편') 하나로 읽는다. 합치기는 아직 없다.
- 화면에서는 커밋을 '기록', 갈래를 '전개'라고 부른다. 세계관을 직접 고치면 render 때 `flushPending`이 바로 '세계관 직접 수정' 기록으로 남기고, 30분 안이면 맨 끝 자동 기록에 이어 붙인다(그 뒤로 갈라진 전개가 없을 때만).
- 성격·소속감·관계 세기는 약함/보통/강함/아주 강함(0.25/0.5/0.75/1)으로 고른다. 인물·단체에는 `notes`(메모)와 `photo`(160px JPEG data URL)가 있다.
- 지우기는 `op:'remove'` patch로 기록한다. 인물·단체를 지우면 이어진 관계, 그 단체의 소속, 하위 단체의 상위 연결도 함께 정리하고(`removeEntity`), 알림의 되돌리기는 지운 것을 다시 추가하는 patch로 되살린다(`restore`). 같은 이름(다른 이름 포함)은 만들기 전에 묻고, 원고 후보에서는 기본으로 체크를 끈다.
- 관계도에서 끌어 옮긴 위치는 `layout`에 저장하고 버전과 무관하다. 휴대폰(폭 600px 미만이거나 눕힌 휴대폰)에서는 관계도가 화면을 채우고, 필터는 위에 뜬 한 줄 칩, 소속 선·사건 영향·범례는 '보기' 시트, 고른 항목은 아래 시트(끌어올리면 상세)로 보인다. 세로 화면에서는 지역이 위→아래로 쌓이게 가로·세로를 바꿔 그리고, 저장 위치는 원래 좌표 그대로다. 테마·도움말·로그아웃은 프로필 사진 메뉴에 있다. 버전 기록에는 이야기 흐름, 타임라인(인물별로 거르기), 비교·되돌리기 세 가지 보기가 있다.
- 원고 붙여넣기: `/api/extract`가 원고 한 화(최대 12,000자)에서 새 인물·단체, 상황 변화, 새 관계, 사건 후보를 뽑는다. 원고 원문은 저장하지 않는다. 같은 호출에서 개연성 검사(`conflicts[]`: 인용 문장, 종류, 관련 id, 이유)도 한다. 비교 기준은 그 화 시점(`chBase`)의 세계관과 그때까지의 사건 10개다. 인용이 원고에 없는 지적은 서버가 버리고, '의도한 거예요'로 넘긴 지적은 화의 `ignored`에 남겨 다시 띄우지 않는다.
- 물어보기: 머리줄의 물어보기 버튼. `/api/ask`가 세계관·원고(최대 약 36,000자, 질문에 나온 이름이 있는 화를 우선)·기록·메모를 읽고 답하고, 근거(인물·단체·배경·화·기록 id)를 칩으로 붙인다. 원고에서 문장을 골라 '고른 문장 설명해 줘'로도 묻는다. 자료는 저장하지 않는다.
- 화별 등장: 원고 본문에서 이름(다른 이름 포함, 두 글자 이상)을 세어 버전 기록 > 화별 등장에 막대로 그린다. 3화 넘게 안 나오면 표시. 관계도의 화 범위 필터도 같은 계산을 쓴다.
- 원고 옆 패널: 그 화에 나온 인물·단체 카드, 화마다 복선 메모(`memos`, 회수 체크). 찾아 바꾸기, 내보내기(TXT·Markdown·인쇄로 PDF).
- 관계도 타임랩스: 관계도의 '기록 재생'으로 지금 전개의 기록을 처음부터 차례로 넘긴다(`stateOf`, 노드 위치는 `layout` 그대로). 그 기록에서 바뀐 노드·관계는 노랗게, 끊긴 관계는 빨간 점선으로 잠깐 보인다.
- 화 ↔ 기록 연결: 화 목록 항목(`chapters[]`)의 `commit`이 그 화 시점의 기록이다. 원고 후보를 반영하거나 원고에서 보낸 사건을 기록하면 자동으로 잇고, 원고 화면의 '이 화 시점'에서 바꾼다. 연결이 없으면 앞 화 중 가장 가까운 연결, 그것도 없으면 지금 기록을 기준으로 본다(`chBase`).
- 인물별 '아는 것': 인물의 `knowledge[]` = `{id(fact_...), text, how(당사자/목격/전해 들음/추측), secret, since(기록 id)}`. 같은 사실은 인물끼리 같은 id를 쓴다. 사건 분석(`/api/analyze`)의 `knows`가 "누가 알게 됐나"를 제안하고, 고른 것은 patch로 기록된다. 인물 카드에 아는 것·모르는 비밀(알게 하기), 관계도에 '이 비밀을 아는 사람만' 필터. 세계관 요약(`worldText`)에 인물마다 최근 8개를 실어 원고 개연성 검사('모를 정보를 앎')와 물어보기가 참고한다.
- 다음에 쓸 거리: 사건 입력 옆 카드(관계도 요약에도 두 개). AI 호출 없이 계산한다(`nextIdeas`): 최근 사건 분석의 '앞으로' 중 그 뒤 사건에 연루되지 않은 인물, 대립·경쟁 '강함' 이상인데 최근 사건 5개에 같이 안 나온 쌍, 회수 안 한 복선 메모(오래된 순), 원고에 3화 넘게 안 나온 인물. 누르면 사건 제목만 채운다.
- 고정(즐겨찾기)한 항목은 저장본의 `pins`에 두고 버전과 무관하다.
- 로그인 전 첫 화면은 소개 페이지, `/privacy`는 개인정보처리방침. 처음 로그인하면 사용 안내가 뜨고, 헤더의 도움말로 다시 볼 수 있다.
- 화면 로직은 `src/legacy/gitstory.js`(프로토타입 스크립트 이식), 예시 데이터는 `src/data/`.

## 스택
- Next.js (App Router, TypeScript)
- Firebase (Firestore, Auth), 프로젝트 `gitstory-snu-2026`
- Vercel 배포

## 빌드 참고
- `npm run build`는 webpack으로 빌드한다(`next build --webpack`). Turbopack 빌드는 firebase-admin을 해시 붙은 이름으로 불러와 Vercel 함수에서 500 오류가 났다.
- 서버 API(`/api/*`)는 Vercel 환경변수 `FIREBASE_SERVICE_ACCOUNT`(서비스 계정 키 JSON 전체)가 필요하다.

## 로컬 실행
```bash
cp .env.example .env.local
npm install
npm run dev
```
